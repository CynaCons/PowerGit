# Design — v0.2 engine + v0.3 shell

Owner-agreed through v0.3. Keep this file short.

## Engine (v0.2)

Separate process, not WinForms, not `net10.0-windows`.

```
frontend  --HTTP-->  127.0.0.1:<port>  PowerGit.Engine (Kestrel)
                                          Process.Start("git")
```

- Project: `src/engine/PowerGit.Engine`, own `Directory.Build.props` so the Git Extensions `UseWindowsForms` does not leak in.
- Bind loopback only. Dev default `http://127.0.0.1:7733`.
- v0.2 does **not** reference `GitCommands` (it cannot until TFM/WinForms leaks are cut). Thin `git` host is the spike.
- Endpoints: `GET /health`, `POST /repos/open`, `GET /repos/current`.
- Git binary: `git` on PATH (`git.exe` on Windows is fine via PATH).

## Shell (v0.3)

Git Extensions Browse information architecture, VS Code Light+ chrome language.

```
┌────┬──────────┬──────────────────────────────────────┐
│nav │ left     │ toolbar  Commit  Fetch  Pull  Push   │
│rail│ tree     ├──────────┬───────────────────────────┤
│    │ branches │ graph    │ message | author | date   │
│    │ remotes  │ (canvas  │ virtualized rows          │
│    │ submods  │  column) │                           │
│    │          ├──────────┴───────────────────────────┤
│    │          │ commit details + file list + diff    │
└────┴──────────┴──────────────────────────────────────┘
```

- Navrail = VS Code activity bar analogue (repos). Light, not the default dark activity bar — Git Extensions is light-first.
- Left tree / bottom panel resizable, collapsible.
- Toolbar above the grid. Commit opens a stub overlay (empty) so the slot exists.

## Theme (v0.3 visual)

Git Extensions is the **behavior** spec. Visuals are a modern React app: MUI panels, nav rail, card layout. Not WinForms, not VS Code.

Shell: grey page (`#f4f6f8`), white AppBar, 12px-radius `Paper` cards with a gap so the background shows. Nav rail is icon-only. Bottom details are tabs inside a Paper, not three flush splitters.

PowerNote-adjacent tokens (primary `#2563eb`, Inter) via `frontend/src/theme.ts`.

| Token | Hex | Role |
|---|---|---|
| `--color-bg` | `#fafafa` | app chrome wash |
| `--color-surface` | `#ffffff` | rail, top bar, sidebar, grid |
| `--color-border` | `#e5e5e5` | hairline splitters |
| `--color-text` | `#1a1a1a` | body |
| `--color-text-muted` | `#737373` | labels, status |
| `--color-primary` | `#2563eb` | active, Commit, lane 0 |
| `--color-active` | `#eff6ff` | selected row, primary wash |
| `--color-hover` | `#f5f5f5` | hover |
| `--color-canvas-bg` | `#f0f0f0` | diff pane |

Type: Inter 14px chrome, Fira Code for hashes/diff. 8px rail buttons, 6px toolbar buttons, 10px overlay radius. Ghost buttons (no filled bricks).

Signature: the **graph column**. Chrome matches PowerNote.

## Graph stack (v0.3.1) — decision

**TanStack Virtual + a Canvas 2D graph column.** Lane model in TypeScript for the prototype (port of GE `RevisionGraph` ideas: lanes, segments, max 40). Engine will own lane assignment later.

Rejected:

| Option | Why not |
|---|---|
| `@gitgraph/react` / SVG full DAG | Dies on real histories |
| vis.js / cytoscape | General graphs, not a revision grid |
| Pixi/WebGL in v0.3 | Overkill until canvas fails a 50k-row budget |

Performance bar (asserted in tests, synthetic 10k rows):

- First paint of the visible window < 100 ms after data is in memory
- Scroll: only visible rows + 1 row of canvas above/below are drawn
- Selecting a row updates the bottom panel without rebuilding the list
